# Sky Work — ระบบติดตามงาน HR

เว็บแอปส่วนตัวสำหรับติดตามงาน งบประมาณ และปฏิทินงาน
เปิดได้ทั้งมือถือ แท็บเล็ต และโน้ตบุ๊ก ข้อมูลซิงก์อัตโนมัติทุกเครื่อง ติดตั้งลงหน้าจอได้เหมือนแอปจริง (PWA)

---

## ขั้นที่ 1 — สร้างฐานข้อมูลบน Supabase (ฟรี)

1. เข้า **supabase.com** → Sign in ด้วย Google
2. **New project**
   - Name: `sky-work`
   - Database Password: ตั้งเอง (จดเก็บไว้)
   - Region: **Southeast Asia (Singapore)**
   - กด **Create new project** แล้วรอ ~2 นาที
3. เมนูซ้าย → **SQL Editor** → **New query**
4. เปิดไฟล์ `supabase/schema.sql` ก๊อปทั้งหมด วางลงไป → กด **Run**
   ต้องขึ้น `Success. No rows returned`
5. เมนูซ้าย → **Project Settings** (รูปเฟือง) → **API**
   เก็บ 2 ค่านี้ไว้ใช้ในขั้นที่ 3
   - **Project URL** → หน้าตาแบบ `https://xxxxxxxx.supabase.co`
   - **anon public** key → ข้อความยาวขึ้นต้นด้วย `eyJ...`

> anon key เปิดเผยได้ ไม่ใช่ความลับ เพราะ Row Level Security ล็อกให้เห็นเฉพาะข้อมูลของบัญชีที่ล็อกอินเท่านั้น
> **ห้ามใช้** `service_role` key เด็ดขาด

### (ทางเลือก) ปิดการยืนยันอีเมล เพื่อให้สมัครแล้วเข้าใช้ได้ทันที

**Authentication → Sign In / Providers → Email** → ปิด **Confirm email** → Save

---

## ขั้นที่ 2 — อัปโหลดขึ้น Vercel

**วิธี A — ลากไฟล์ (ง่ายสุด ไม่ต้องใช้ GitHub)**

1. เข้า **vercel.com** → Sign in ด้วย Google
2. **Add New… → Project → Deploy** (หรือหน้า vercel.com/new)
3. ลากโฟลเดอร์ **`public`** ทั้งโฟลเดอร์ไปวาง
4. กด **Deploy** รอสักครู่ จะได้ลิงก์ `https://xxxx.vercel.app`

**วิธี B — ผ่าน GitHub (อัปเดตง่ายกว่าในระยะยาว)**

1. สร้าง repository ใหม่บน GitHub แล้วอัปโหลดโฟลเดอร์ `sky-work` ทั้งชุด
2. Vercel → **Add New → Project → Import Git Repository** → เลือก repo นี้
3. ตั้งค่าตอน Import
   - Framework Preset: **Other**
   - Root Directory: **`.`** (ค่าเริ่มต้น)
   - Output Directory: **`public`**
4. กด **Deploy**

---

## ขั้นที่ 3 — เปิดใช้งานครั้งแรก

1. เปิดลิงก์ Vercel ที่ได้มา
2. หน้าแรกจะถามค่าเชื่อมต่อ ใส่ **Project URL** และ **anon public key** จากขั้นที่ 1 → กด **เชื่อมต่อ**
3. ใส่อีเมลและรหัสผ่านที่จะใช้ล็อกอิน (อย่างน้อย 6 ตัว) → กด **สมัคร / เข้าสู่ระบบ**
   ครั้งแรกระบบจะสร้างบัญชีให้เอง ครั้งต่อไปเครื่องจะจำไว้ ไม่ต้องล็อกอินซ้ำ
4. เข้าเมนู **ตั้งค่า → นำเข้า CSV** → เลือกไฟล์ `data/skywork-tasks.csv` → งานเดิม 60 รายการเข้าระบบทันที

ทำขั้นที่ 3 ซ้ำอีกครั้งบนเครื่องที่สอง (ใส่ URL + key + ล็อกอินด้วยอีเมลเดิม) จะเห็นข้อมูลชุดเดียวกัน

## ติดตั้งลงหน้าจอ

**Android (Chrome)** — เปิดเว็บ → จุดสามจุดมุมขวาบน → **เพิ่มลงในหน้าจอหลัก** → เปิดได้เต็มจอเหมือนแอป

**iPhone / iPad (Safari)** — ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**

**Windows / macOS (Chrome หรือ Edge)** — ไอคอนติดตั้งท้ายช่อง URL → **ติดตั้ง**

## รูปแบบไฟล์ CSV สำหรับนำเข้า

บรรทัดแรกต้องเป็นหัวคอลัมน์ (สลับลำดับได้ ขาดคอลัมน์ไหนก็ได้ ยกเว้น **ชื่องาน**) บันทึกเป็น **CSV UTF-8**

```csv
ชื่องาน,กลุ่ม,ประเภท,สถานะ,ผู้รับผิดชอบ,วันที่,บริษัท,งบ,ใช้จริง,รายละเอียด
อบรมดับเพลิงขั้นต้น,งานประจำปี,อบรม,รอดำเนินการ,วิม,2026-07-16,LeKise (LKL),37800,0,จองวิทยากรแล้ว
```

- **วันที่** รูปแบบ `ปี-เดือน-วัน` เช่น `2026-07-16` (เว้นว่างได้ถ้าเป็นงานประจำ)
- **สถานะ** ใช้ได้ 3 แบบ: `รอดำเนินการ` / `กำลังดำเนินการ` / `เสร็จสิ้น`
- **กลุ่ม** และ **บริษัท** ถ้าไม่ตรงกับที่มีอยู่ ระบบจะสร้างให้ใหม่อัตโนมัติ
- การนำเข้าจะ **เพิ่มต่อท้ายเสมอ** ไม่ลบของเดิม

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| ค้างที่ "กำลังโหลด…" | URL หรือ anon key ผิด — ล้างค่าแล้วใส่ใหม่ที่ Console: `localStorage.clear()` แล้วรีเฟรช |
| สมัครแล้วเข้าไม่ได้ | ยังไม่ได้ปิด Confirm email ในหน้า Authentication หรือยังไม่ได้กดยืนยันในอีเมล |
| บันทึกแล้วขึ้น "บันทึกไม่สำเร็จ" | ยังไม่ได้รัน `schema.sql` หรือ RLS policy ไม่ถูกสร้าง — รันสคริปต์ซ้ำอีกครั้ง |
| แก้จากมือถือแล้วโน้ตบุ๊กไม่อัปเดต | ยังไม่ได้เปิด Realtime — รันบรรทัด `alter publication supabase_realtime add table public.rows;` |
| อัปเดตเว็บแล้วยังเห็นของเก่า | Service worker แคชไว้ — ปิดแท็บทั้งหมดแล้วเปิดใหม่ หรือ Hard refresh |

## หมายเหตุทางเทคนิค

- ไม่มี build step — เป็น static HTML/CSS/JS ล้วน
- โครงข้อมูล: ตาราง `rows` เดียว แยกด้วยคอลัมน์ `kind` (`items` = งาน, `ledger` = รายการเงิน, `meta` = การตั้งค่า) เก็บเนื้อหาใน `data` แบบ JSONB
- เปลี่ยนโครงข้อมูลภายหลังไม่ต้อง migrate ตาราง
- โควตาฟรีของ Supabase (500MB) รองรับข้อมูลระดับนี้ได้หลายปี
